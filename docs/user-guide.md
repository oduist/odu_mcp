# Руководство пользователя Connect MCP

Connect MCP позволяет работать с данными Odoo из MCP-совместимого AI-клиента. Все
операции выполняются от имени вашего обычного пользователя Odoo и ограничены:

- вашими правами доступа, record rules и доступными компаниями в Odoo;
- назначенным администратором MCP-профилем;
- разрешёнными в профиле моделями, полями, операциями и лимитами;
- обязательным согласованием изменений, если оно требуется политикой.

MCP не выдаёт дополнительных прав. Если действие запрещено в Odoo или в
MCP-профиле, AI-клиент также не сможет его выполнить.

## Что потребуется

Администратор должен предоставить:

1. адрес MCP-сервера, например `https://mcp.example.com/mcp`;
2. назначение **Connect MCP > User Access** для вашей учётной записи;
3. MCP-профиль с нужными моделями и операциями.

API-ключ создаёт сам пользователь. Не отправляйте ключ администратору и не
вставляйте его в чаты, задачи или скриншоты.

## Создание MCP API-ключа

1. Откройте Odoo и нажмите на аватар пользователя.
2. Перейдите в **My Profile / Preferences**.
3. Откройте раздел безопасности учётной записи и управление API-ключами.
4. Нажмите **New API Key**.
5. В поле **Access** оставьте **MCP only**.
6. Укажите понятное имя, например `Claude Desktop on MacBook`.
7. Выберите ограниченный срок действия ключа.
8. Создайте ключ и сразу сохраните показанное значение в менеджере секретов.

Odoo показывает полный ключ только один раз. Если ключ потерян, удалите его и
создайте новый.

Ключ **All APIs** для MCP не подходит. MCP endpoint принимает только ключи с
точным scope `mcp`.

## Подключение MCP-клиента

Клиент должен использовать Streamable HTTP и передавать ключ как Bearer token.
Общий пример конфигурации:

```json
{
  "url": "https://mcp.example.com/mcp",
  "headers": {
    "Authorization": "Bearer YOUR_CONNECT_MCP_API_KEY"
  }
}
```

Название полей зависит от MCP-клиента. Ищите настройку HTTP MCP server, remote
MCP server или Streamable HTTP. Stdio-команды и локальный процесс для Connect MCP
не используются.

После подключения попросите клиента вызвать `odoo_whoami`. В ответе должны
совпасть ваше имя пользователя Odoo, компания и назначенный MCP-профиль.

## Доступные возможности

Набор инструментов зависит от конфигурации sidecar и вашего MCP-профиля.

### Чтение данных

Обычно доступны:

- `odoo_server_info` — версия Odoo, профиль и доступные возможности;
- `odoo_whoami` — текущий пользователь, компания и язык;
- `odoo_list_models` — модели, разрешённые вашим профилем;
- `odoo_describe_model` — доступные поля и операции модели;
- `odoo_search_records` — поиск и чтение записей;
- `odoo_get_record` — чтение записей по точным ID;
- `odoo_count_records` — подсчёт записей;
- `odoo_aggregate_records` — разрешённые агрегаты и группировки;
- чтение вложений и формирование отчётов, если это разрешено профилем.

Администратор может задать обязательный domain. Он всегда добавляется к вашему
поиску через логическое `AND`, и клиент не может его снять.

### Изменение данных

Изменения выполняются в два этапа:

1. AI-клиент вызывает инструмент `odoo_preview_*` и создаёт неизменяемый план.
2. MCP-администратор проверяет план в Odoo и одобряет или отклоняет его.
3. После одобрения клиент вызывает `odoo_execute_approved_change`.

Preview ничего не изменяет в бизнес-данных. Он показывает:

- тип действия;
- модель и количество записей;
- разрешённые изменяемые поля;
- сокращённый diff;
- уровень риска;
- срок действия approval.

Каждый preview использует idempotency key. Повтор с тем же ключом и тем же
payload возвращает существующий план. Использовать тот же idempotency key для
другого payload нельзя.

Изменения исполняются только один раз. Повторный execute возвращает уже
сохранённый результат и не выполняет операцию повторно.

## Как формулировать запросы AI-клиенту

Для чтения полезно явно указывать:

- модель или бизнес-объект;
- компанию и период;
- нужные поля;
- максимальное количество записей;
- требуемую сортировку или группировку.

Пример:

```text
Найди до 20 клиентов моей текущей компании, изменённых за последние 7 дней.
Покажи только название, email и дату изменения. Ничего не изменяй.
```

Для изменения сначала запросите preview:

```text
Подготовь preview изменения email партнёра с ID 42 на new@example.com.
Не выполняй изменение до одобрения в Odoo.
```

Не просите клиента запускать несколько Odoo tools параллельно для одной
учётной записи. Sidecar всё равно сериализует такие операции, а лишний
параллелизм может закончиться ошибкой `user_operation_busy`.

## Approvals и уведомления

Состояние плана доступно через инструмент `odoo_get_change_status` и ресурс:

```text
odoo://approval/<approval_id>
```

Если MCP-клиент поддерживает `subscriptions/listen`, он может получить
уведомление, что approval или запись изменились. Уведомление содержит только
URI ресурса. После него клиент перечитывает ресурс с вашими текущими правами.

## Типовые ошибки

| Код или ситуация | Что означает | Что делать |
| --- | --- | --- |
| `401 Unauthorized` | Ключ неверен, истёк, отозван или не имеет scope `mcp` | Создать новый ключ **MCP only** |
| `mcp_access_not_configured` | Для пользователя нет назначения User Access | Обратиться к администратору |
| `inactive_mcp_access` | Назначение, профиль или пользователь отключён | Обратиться к администратору |
| `policy_denied` / `field_denied` | Модель, операция или поле не разрешены профилем | Уточнить рабочую задачу и запросить изменение профиля |
| `access_denied` | Операцию запретили ACL, record rule, company rule или forced domain | Проверить права пользователя в Odoo |
| `rate_limit_exceeded` | Превышен минутный лимит | Подождать и повторить позже |
| `daily_quota_exceeded` | Исчерпана дневная квота UTC | Дождаться следующего дня или обратиться к администратору |
| `user_operation_busy` | Предыдущая операция этого пользователя ещё выполняется | Не запускать tools параллельно, повторить позже |
| `approval` остаётся `pending` | План ещё не рассмотрен | Открыть Approval Inbox или связаться с MCP-менеджером |
| `approval` стал `expired` | Истёк срок действия плана | Создать новый preview |

## Отзыв ключа и завершение работы

Если устройство потеряно, клиент больше не используется или ключ мог попасть
третьим лицам:

1. откройте управление API-ключами в профиле Odoo;
2. удалите соответствующий ключ;
3. удалите его из конфигурации MCP-клиента;
4. при необходимости создайте новый ключ с новым именем и коротким сроком.

Отзыв ключа не удаляет audit log и ранее созданные approvals.

## Правила безопасности

- Используйте отдельный MCP-ключ для каждого устройства или клиента.
- Выбирайте минимальный разумный срок действия.
- Не используйте ключ администратора Odoo.
- Не храните ключ в репозитории, shell history или обычном текстовом файле.
- Перед одобрением проверяйте модель, ID записей, diff и уровень риска.
- Если результат AI выглядит неожиданно, не одобряйте план и создайте новый
  запрос с более точными ограничениями.
